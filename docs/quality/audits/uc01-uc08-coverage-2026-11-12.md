# PlantOps — matriz de evidencias de pruebas UC-01 a UC-08

**Fecha de corte:** 2026-11-12. **Código funcional examinado:** `feat/plantops-assets-module`, commit [`60d0f28`](https://github.com/andresvalencia72/plantops/commit/60d0f28d07f67918ae4f439eb5bf4dd4fc5592f8), PR #70. **Complemento UI demo:** PR #71, commit [`6cd264b`](https://github.com/andresvalencia72/plantops/commit/6cd264b471e4b192e60bfa10830c008ba78a8b4a). **Estado:** auditoría de lectura; sin autorización de merge, integración ni despliegue.

## Leyenda y niveles de confianza

- **PG:** Vitest de integración sobre PostgreSQL desechable y esquemas reales.
- **HTTP:** NestJS/Supertest, sesiones de prueba respaldadas por PostgreSQL, errores y guardas del servidor.
- **UI:** React Testing Library/Vitest, API simulada para probar presentación y contratos.
- **Chrome + PG:** Playwright conectado al NestJS real y un PostgreSQL desechable mediante el modo aislado. **La sesión se fabrica para la prueba; no es un login Google real.**
- **Auth-build:** Chrome contra compilación Vite explícitamente autenticada, con API interceptada, sin fixtures ni escrituras reales.

Una suite presente y verde **no constituye 100 % de cobertura**: no hemos obtenido una métrica de cobertura de ramas/instrucciones ni ensayado un piloto HTTPS real. Los estados de CI citados son los **ya verificados en GitHub**, no una nueva ejecución durante esta auditoría.

## Brechas priorizadas para la revisión del propietario

1. **P1, defecto reproducido:** el lector de incidencias convierte `reported_at` de PostgreSQL a `Date` y su cursor a milisegundos. Filas creadas dentro del mismo milisegundo pueden desaparecer de páginas posteriores. Prueba actual [incidents-read-http](../../../apps/api/test/incidents-read-http.integration-spec.ts) usa marcas temporales de horas distintas y no lo detecta. Referencia correcta en [work-order-reader](../../../apps/api/src/work-orders/drizzle-work-order-reader.ts). La reproducción PostgreSQL 17 previa se hizo en contenedor desechable, no en el piloto.
2. **P1 de publicación, sin defecto demostrado:** pruebas E2E con usuarios invitados reales detrás de HTTPS, cookies/CSRF, cabeceras/proxy y control de observabilidad/backup/restore. Ningún resultado de CI actual elimina ese bloqueo.
3. **P2:** pruebas de accesibilidad para restauración del foco, ARIA y localización en la demo; véase [auditoría pública](public-demo-accessibility-2026-11-12.md).
4. **P2 de volumen:** historial de reasignaciones limitado a 1000 y selector de activos sin paginación, antes de un despliegue multiempresa con mucha carga. Medir antes de optimizar.
5. **P3:** separar pruebas de humo de navegador Chrome y ejecución real en Safari/Firefox, con datos y cuentas autorizados; añadir matriz de estados vacíos, errores y lector de pantalla con tecnología asistiva.

**Decisión vigente:** ninguna modificación de negocio, integración de PR, fusión de `main`, activación de escrituras fuera del laboratorio, migración del piloto o despliegue está autorizada. El propietario debe revisar personalmente el código antes de decidir el siguiente paso.
